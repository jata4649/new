# 本番化前チェックリスト

このシステムは**現金を受け取らない非公開のテスト環境**として構築されている。
本番稼働（現金決済・一般公開）へ移行する前に、以下をすべて完了させること。

> このリストは技術的な確認項目の整理であり、法的助言ではない。
> 法務・会計・許認可については必ず専門家の確認を受けること。

---

## A. 法務・許認可（最優先）

- [ ] **賭博罪・景品表示法**に関する法務確認を完了した
  - [ ] ハズレ枠が存在しない（全スロットに景品が割り当たる）ことを確認した
  - [ ] 景品の価値と販売価格の関係について確認を受けた
- [ ] **古物商許可**を取得した
  - [ ] `inventories` の `acquisition_source` / `acquired_from` / `acquired_at` が
        古物台帳として要件を満たすか確認した
  - [ ] 台帳のエクスポート機能を実装した
- [ ] **資金決済法**（前払式支払手段）について確認を受けた
  - [ ] 有償ポイントの有効期限が 180 日（6 か月未満）で固定されている
  - [ ] 6 か月超へ変更する場合、届出・供託の要否を確認した
- [ ] **特定商取引法に基づく表記**を掲載した
- [ ] **利用規約・プライバシーポリシー**を掲載し、同意取得の導線を実装した
- [ ] **資金移動業に該当しない**ことを確認した
      （ポイントの現金払戻し・ユーザー間譲渡を実装していないこと）
- [ ] 実在 IP（作品名・キャラクター・ロゴ）を一切使用していないことを確認した
  - [ ] `prisma/seed/ng-words.ts` のチェックが CI で実行されている
  - [ ] 本番投入する在庫データに対しても同じ検査を行った

---

## B. 決済

- [ ] 正式な決済事業者の審査に通過した
- [ ] `PaymentProvider` インターフェースの実装を差し替えた
- [ ] `PAYMENT_PROVIDER` の値が `mock` 以外になっている
- [ ] **テスト決済の管理画面・API を本番で無効化した**
      （`TEST_PAYMENT_OPERATE` 権限を誰にも付与しない、またはルートごと削除）
- [ ] カード番号を保存・ログ出力していないことを確認した
- [ ] Webhook の署名検証が本番の鍵で動作することを確認した
- [ ] Webhook の重複・遅延・順序逆転に対する挙動を本番環境で検証した
- [ ] 返金フローで `point_lot_consumptions` を辿って元ロットへ戻ることを確認した

---

## C. データベース・権限

- [ ] アプリが**実行時ロール `oripa_app`** で接続している
      （テーブル所有者 `oripa` ではない）
- [ ] 追記専用テーブルに対する `oripa_app` の UPDATE / DELETE 権限が剥奪されている
  ```sql
  SELECT grantee, table_name, privilege_type
  FROM information_schema.role_table_grants
  WHERE grantee = 'oripa_app'
    AND table_name IN ('point_ledger_entries','point_lot_consumptions',
                       'draw_transactions','draw_results','audit_logs')
    AND privilege_type IN ('UPDATE','DELETE');
  -- 0 行であること
  ```
- [ ] 追記専用トリガが全対象テーブルに設定されている
  ```sql
  SELECT tgrelid::regclass FROM pg_trigger WHERE tgname LIKE '%append_only%';
  ```
- [ ] **管理画面から任意 SQL を実行できる機能が存在しない**ことを確認した
- [ ] DBA ロールを分離し、`oripa_slots.draw_order` へアクセスできる人物を限定した
- [ ] 本番 DB への直接アクセスが踏み台経由になり、監査ログが残る
- [ ] コネクションプールのサイズを負荷試験の結果に基づいて設定した
- [ ] PgBouncer を使う場合、transaction pooling とインタラクティブ
      トランザクションの相性を検証した

## D. バックアップ・復旧

- [ ] 自動バックアップが設定されている（頻度・保持期間を決定した）
- [ ] **リストアを実地で試した**（手順書どおりに復旧できることを確認した）
- [ ] PITR（Point-In-Time Recovery）の可否と RPO / RTO を決めた
- [ ] 手順書 [08-runbook.md](./08-runbook.md) / [09-backup-restore.md](./09-backup-restore.md)
      が最新の構成と一致している

## E. セキュリティ

- [ ] すべての秘密情報が環境変数または秘密管理サービスにあり、コードに無い
- [ ] `AUTH_SECRET` を本番用に生成し直した（開発用と共有していない）
- [ ] `MOCK_PAYMENT_WEBHOOK_SECRET` の既定値を使っていない
- [ ] `SITE_BASIC_AUTH_PASSWORD` を本番用に変更した（公開する場合は方針を決定した）
- [ ] HTTPS が強制され、HSTS が設定されている
- [ ] CSP（Content-Security-Policy）を設定した
- [ ] レート制限が有効で、Redis が冗長化されている
- [ ] ログイン試行のレート制限とアカウントロックが動作する
- [ ] 管理画面に IP 制限または VPN 必須の運用を適用した
- [ ] アップロードの形式・容量制限が有効（マジックバイト検証を含む）
- [ ] エラーレスポンスに内部情報（スタックトレース・SQL・接続先）が含まれない
- [ ] 監査ログの `before` / `after` にパスワードハッシュ・トークンが入っていない
      （`redact()` を通している）
- [ ] 依存パッケージの脆弱性スキャンを CI に組み込んだ
- [ ] 管理者アカウントに多要素認証を導入した（または導入計画がある）

---

## F. アプリケーション

- [ ] `SITE_ACCESS_MODE` の値と公開方針が一致している
- [ ] 一般公開する場合、`robots.txt` と `X-Robots-Tag` の設定を見直した
- [ ] `NEXT_PUBLIC_TEST_MODE_BANNER` を本番向けに設定した
- [ ] ヘルスチェック（`/api/health`）が監視サービスから叩かれている
- [ ] Sentry（または同等のサービス）を `setErrorReporter()` へ接続した
- [ ] `pnpm points:reconcile` を定期実行し、不整合を検知したら通知する
- [ ] 有効期限切れバッチ（`points:expire`）を定期実行している
- [ ] 冪等性キー・期限切れセッションの掃除バッチを設定した
- [ ] タイムゾーンが UTC 保存 / JST 表示で一貫している

---

## G. 公正性・透明性

- [ ] 当選確率と総口数・残り口数を画面に表示している
- [ ] 販売開始後に価格・総口数・景品構成・確率を変更できないことを確認した
- [ ] `slot_order_commit` を公開し、販売終了後に `serverSeed` を公開する運用を決めた
- [ ] 販売停止・在庫の状態変更がすべて `audit_logs` に残ることを確認した
- [ ] 抽選履歴・ポイント履歴をユーザーが自分で確認できる
