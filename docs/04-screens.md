# 画面一覧

スマートフォンファースト。すべての画面を 375px 幅で成立させたうえで、
広い画面へ拡張する。日本語 UI。日時表示は Asia/Tokyo。

## 2. 管理画面 `/admin`

| 画面           | パス                      | 必要権限          | フェーズ |
| -------------- | ------------------------- | ----------------- | -------- |
| ダッシュボード | `/admin`                  | `user:read`       | 2        |
| ユーザー一覧   | `/admin/users`            | `user:read`       | 2        |
| ユーザー詳細   | `/admin/users/[id]`       | `user:read`       | 2        |
| 在庫一覧       | `/admin/inventories`      | `inventory:read`  | 4        |
| 在庫登録       | `/admin/inventories/new`  | `inventory:write` | 4        |
| 在庫詳細・編集 | `/admin/inventories/[id]` | `inventory:read`  | 4        |
| オリパ一覧     | `/admin/oripas`           | `oripa:read`      | 4        |
| オリパ作成     | `/admin/oripas/new`       | `oripa:write`     | 4        |
| オリパ詳細     | `/admin/oripas/[id]`      | `oripa:read`      | 4        |

オリパ詳細は 1 画面で完結させている（景品割当・公開条件・公開・販売停止）。
別画面へ分けると「割当は終わったが公開条件を満たしていない」状態が見えにくくなり、
公開直前まで不足に気付けないため。

公開前プレビューは専用画面を作らず、ユーザー向け詳細（`/oripas/[slug]`）を使う。
表示ロジックを二重化すると「プレビューでは見えたのに公開後は違う」というズレが生まれる。
下書きは公開クエリの対象外なので、公開するまでユーザーからは見えない。
| 抽選履歴 | `/admin/draws` | `draw:read` | 5 |
| 発送申請一覧 | `/admin/shipping-requests` | `shipping:read` | 7 |
| 発送申請詳細 | `/admin/shipping-requests/[id]` | `shipping:update` | 7 |
| 監査ログ | `/admin/audit-logs` | `audit:read` | 8 |
| Mock 決済操作 | `/admin/test-payments` | `test_payment:operate` | 3 |

### ダッシュボードの表示項目（MVP は簡易集計）

登録ユーザー数 / 販売中オリパ数 / 総抽選回数 / 当日抽選回数 /
発行ポイント / 消費ポイント / 未処理発送申請 / 在庫数 /
直近のエラー / 直近の管理者操作

### オリパ管理での表示

- **期待値**：スロットの参考価格合計 ÷ 総口数（管理画面のみ。整数比で保持し表示時に整形）
- **当選確率**：ランクごとの口数 ÷ 総口数
- **公開条件のチェックリスト**：未充足の項目を具体的に表示する

## 3. 共通のUI規約

### 危険な操作

| 操作                         | 必要なもの                                         |
| ---------------------------- | -------------------------------------------------- |
| ユーザー停止 / 退会処理      | 確認ダイアログ + 理由入力                          |
| ポイント調整                 | 確認ダイアログ + 理由入力 + 調整後残高のプレビュー |
| オリパ販売停止               | 確認ダイアログ + 理由入力                          |
| 発送申請の取消し             | 確認ダイアログ + 理由入力                          |
| ポイント交換（ユーザー操作） | 確認ダイアログ（**取消不可**である旨を明示）       |
| 抽選実行                     | 確認ダイアログ（消費ポイントと残高の明示）         |

### アクセシビリティ

- キーボードのみで主要操作が完了する
- フォーカスリングを常に視認できる（`:focus-visible`）
- `prefers-reduced-motion` で演出アニメーションを抑制する
- 色だけに依存しない（ランクはテキストラベルも併記）
- 画像に代替テキストを付ける
- ピンチズームを禁止しない

### 表示の原則

- 金額・ポイントは 3 桁区切り（`formatPoints` / `formatYen`）
- 当選確率は `formatPercent`（小数 3 桁）または `formatOdds`（1/n 形式）
- 日時は JST 表示、`<time datetime="">` には UTC の ISO 文字列
- テスト環境では常に「現金決済は行われません」のバナーを表示する
